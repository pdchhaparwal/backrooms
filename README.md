# The Backrooms (MGT656 team 656-mba-backrooms)

A walking-skeleton web game: Django + Postgres, deployed to Render.

## Routes
| Path | What |
|---|---|
| `/accounts/login/` | Login (variant A or B) |
| `/accounts/signup/` | Sign up |
| `/` | Play Now page (variant A or B, login required) |
| `/instructions/` | Instructions (variant A or B, login required) |
| `/play/` | 5-second playable demo (`/play/?t=30` for a longer run) |
| `/ef88062` | A/B test page (public) |
| `/ef88062/stats` | A/B stats JSON |
| `/admin/` | Django admin (admin account) |

Page variants are random per visitor and sticky for the session. Force one with `?v=a` or `?v=b`.

Controls: W/↑ forward, S/↓ back, A/← turn left, D/→ turn right, Space attack, R restart, M mute.

## Grader accounts
Created by `python manage.py seed` (safe to run repeatedly):
- `admin@example.com` (superuser): password from `SEED_ADMIN_PASSWORD`
- `player1@example.com`, `player2@example.com`: password from `SEED_PLAYER_PASSWORD`

## Run locally
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export DEBUG=true            # uses SQLite unless DATABASE_URL is set
python manage.py migrate
python manage.py seed        # local password: backrooms-local-only
python manage.py runserver
```

## Tests
```bash
python manage.py test        # set DATABASE_URL=postgresql://... to run against Postgres
```

## Deploy (staging)
`render.yaml` is a Render Blueprint. Environment variables:
| Var | Value |
|---|---|
| `DATABASE_URL` | Neon Postgres connection string (`postgresql://...?sslmode=require`) |
| `SECRET_KEY` | generated by Render |
| `SEED_ADMIN_PASSWORD`, `SEED_PLAYER_PASSWORD` | grader passwords (share privately, never commit) |

Every boot runs `migrate` and `seed`, then gunicorn on `$PORT`.

## Team config
`docs/mgt656/team.yaml` drives the A/B page: the URL hash is `sha1(team)[:7]` and the page lists every member.
